# 03 · AI, camera and audio: feasibility, options and cost gates

> **Design prototype. Purchase and wiring HOLD.** Read the [engineering review](13-design-review.md) before using this page. It records unresolved budget, rated power and protection requirements.

## 1. What "AI" can honestly mean on this robot

| Claim | Feasible on the Pico 2 W alone? | Reason |
|---|---|---|
| Chatbot / spoken conversation | **No** | RP2350: 520 KB SRAM, 4 MB flash, up to 150 MHz (Raspberry Pi docs). Language models need gigabytes of memory. |
| Person detection from camera images | **No** (not reliably, not at a useful rate) | Not enough RAM for frames plus a model; the Pico has no camera interface on this board |
| Speech recognition | **No** (beyond a few keyword-spotting tricks) | Same reasons |
| Closed-loop control, sensor fusion, safety, games, UI | **Yes** | Ideal job for a microcontroller |

So the design uses a **web AI model** (user's choice) through a **laptop bridge** (user-approved). The robot itself does **sensing, actuation and safety**. When the AI is unavailable, the robot says so and switches to offline games ([02](02-architecture.md) §6). **It never pretends.**

Language to use in school evidence: *"Pip's conversation is generated by a cloud language model, reached through a laptop bridge. Pip's movement, tracking control loops and safety run on the Raspberry Pi Pico 2 W."*

## 4. Web AI provider: OpenRouter (provisional)

Checked against OpenRouter's own documentation on 2026-10-19:
- Endpoint: `https://openrouter.ai/api/v1/chat/completions`, **OpenAI-compatible**, so the bridge can use any OpenAI-style client by setting `base_url`. Authentication: `Authorization: Bearer <OPENROUTER_API_KEY>`.
- **Billing:** a prepaid **credit** balance in **USD**. Buying credits carries a **5.5% fee (US$0.80 minimum)**. Pricing is per model per token (see the OpenRouter models page).
- **Free models:** 50 requests/day in total without purchased credits; 1000 requests/day once at least 10 credits have been purchased (FAQ). Free models can be rate-limited or withdrawn, so don't rely on them for a demo day.
- **Per-key credit limits** exist. Requests fail with HTTP 402 when a key's limit is used up. **Set a small limit** on Pip's key.
- **Logging:** the FAQ says prompts and completions are **not logged by default**. The upstream model provider's own policy still applies, so pick providers accordingly.
- **Audio:** some models accept `input_audio` (base64), and some can return audio (`modalities: ["text","audio"]`, streaming only). This is an option, not the default (§5).

**OpenCode vs. OpenRouter:** OpenCode is a coding-assistant *client*. OpenRouter is a model *API*. Pip's bridge needs an **API key with credit** from OpenRouter (or another API provider). Do not assume any coding-tool subscription gives API credit that Pip's bridge can use. Check the terms of any plan before relying on it. *(OpenCode plan terms were not checked in this round.)*

**Account age / child use:** OpenRouter's Terms of Service and the chosen model provider's usage policy were **not reviewed in this round**. An **adult** (parent or teacher) must own the account and key and check the terms for an app that talks with children before any child uses it.

## 5. Recommended AI pipeline and cost gates

| Stage | Default (gate 0: lowest cost and best privacy) | Upgrade (only after it passes the gate) |
|---|---|---|
| Person tracking | **Local on the laptop** (OpenCV / MediaPipe-class detector). Images never leave the laptop. | — (no reason to send video to the cloud) |
| Speech-to-text | **Local on the laptop** (Whisper-class model) | Cloud STT or an audio-input LLM, if local is too slow or inaccurate (gate G2) |
| Conversation | **OpenRouter text model**, short replies (≤ 2 sentences), child-safe system prompt, output filter | A bigger model (gate G3) |
| Text-to-speech | **Local voice** on the laptop (OS voice or Piper-class) | Cloud TTS / audio-output model (gate G2) |

Cost gates (decide *before* spending):

| Gate | Question | Pass criterion |
|---|---|---|
| G0 | Hardware budget approved? | D1 resolved ([00](00-status-assumptions-decisions.md)) |
| G1 | API account owned by an adult, key limited, terms checked? | Yes / yes / yes |
| G2 | Is local STT/TTS too poor? | Measured: STT word error with kids' speech, latency > 3 s, or a child can't understand the voice |
| G3 | Is the model's answer quality too poor? | Rated in the evidence log (appropriateness, clarity) |

**Ongoing API cost (kept separate from the hardware budget).** Don't guess a number. Measure it:
`session cost ≈ Σ over turns (prompt_tokens × input_price + completion_tokens × output_price)`. The bridge logs token counts per turn (OpenRouter responses include usage). Report cost per 10-minute session from real logs. Add the 5.5% top-up fee.

## 6. Privacy and child safety for the AI part

- **No images or raw audio go to the cloud** in the default pipeline. Only transcribed text does.
- Nothing is stored by default. Evidence logs keep numbers and redacted text, not recordings.
- System prompt: a friendly companion for ages 5–8; short answers; never asks for personal information (name of school, address, photos); deflects unsafe topics to "ask a grown-up"; always encourages physical play.
- Output filter on the laptop (blocklist + length limit + a re-ask). Keep a **parent kill switch** on the bridge UI.
- Get consent from the teacher and parents before any test where a child's voice or image is processed. Follow school policy (D8).

## 7. Network feasibility notes

- The Pico 2 W radio is **2.4 GHz 802.11n** (Raspberry Pi docs; note the page also shows a conflicting dual-band line, so treat as 2.4 GHz only). The XIAO is also 2.4 GHz.
- School networks often block device-to-device traffic. Fallback: a **laptop hotspot** (Pip devices join it; the laptop keeps internet on its other interface where the OS supports that).
- Bandwidth estimate: QVGA JPEG at 8 fps ≈ 0.5–1.5 Mbit/s, plus 256 kbit/s mic upstream and 256 kbit/s speaker downstream. That is comfortable for 2.4 GHz at room range. **Measure it.**
