# Pip illustrations: wiring diagrams and assembly details

The images in `docs/images/wiring/` and `docs/images/assembly-detail/` are generated by the Python code in this folder. The diagrams are drawn from editable code rather than generated with an AI image tool. The close-ups are renders of the real v0.3 CAD meshes.

**Pip has not been built.** No image is a photo. The wiring diagrams are logical maps, not physical layouts, and every circuit in them is on HOLD ([docs/04](../docs/04-wiring-pin-plan.md)). The CAD close-ups show placeholder envelopes for bought parts. None of them proves that a part fits or can be inserted.

## Regenerate

```bash
scripts/illustrations.sh                          # everything; the CAD renders take about 4 minutes
scripts/illustrations.sh --set wiring             # wiring | vectors | cad
scripts/illustrations.sh --only 04-body-power-split 08-cable-route
scripts/illustrations.sh --strict                 # exit 1 if any label overlaps another or leaves the canvas
```

The script needs [uv](https://docs.astral.sh/uv/). It runs Python 3.12 in a temporary environment with pinned `matplotlib`, `numpy` and `manifold3d`, so nothing is installed system-wide. The text uses the DejaVu Sans font bundled with matplotlib, to reduce font differences between machines.

Every run checks each label's box against every other label and against the canvas edge, and prints any collision. It cannot tell whether a leader line crosses another line or points at the right feature, so look at each changed image before committing it.

## Where to edit

| File | Contents |
|---|---|
| `kit.py` | Shared drawing kit: colours, wire-net colours, status badges, font sizes, components, wires, tags, callouts and the collision check |
| `wiring.py` | Six wiring diagrams. Each layout and its labels are written in one function |
| `assembly_vectors.py` | Code-drawn Details 1, 2, 9, 10 and 13 |
| `assembly_cad.py` | CAD-rendered Details 3–8, 11 and 12 |
| `build.py` | Command line used by `scripts/illustrations.sh` |

**Labels and positions.** Every coordinate is a canvas pixel, with x to the right and y down, as in SVG. `component(id, x, y, width, height, title, sub, pins=...)` draws a box. Each pin is `(name, side, offset, label, net)`. `c.P(id, pin)` returns the pin's position for drawing wires. Callouts in the CAD files take a 3D anchor in assembly millimetres (+X forward, +Y robot's left, +Z up) and a canvas position for the label box.

**Colours** are in `kit.NETS`:

| Net | Colour |
|---|---|
| 5 V | Red |
| 3.3 V | Magenta |
| GND | Black |
| SDA | Blue |
| SCL | Yellow |
| Signal | Teal |
| Motor terminals A and B | Purple and brown. Each is drawn as a separate conductor, never as one joined net |
| Wi-Fi data | Dotted grey |
| Proposed route | Dashed orange |

On Wiring 2, a small chip beside each W13 tag shows that B7 conductor's insulation colour from Core's product page. For example, the 3.3 V conductor is a red wire on a magenta net.

**Wire IDs and facts** come from [docs/04](../docs/04-wiring-pin-plan.md): W1–W17, W13a–d, C1–C9, BOM B-rows, open items WO0–WO7 and gates PG1–PG7. If docs/04 changes, update `wiring.py` to match, regenerate, and compare every wire ID and pin label against 04.

## Editable SVG versus regenerated PNG

- **Wiring 1–6 and Details 1, 2, 9, 10 and 13** ship as PNG plus SVG. The SVG keeps every label as a real `<text>` element, not outlined glyphs, so it can be edited in Inkscape, Figma or a text editor. The font is set to `'DejaVu Sans', 'Helvetica Neue', Arial, sans-serif`. A hand edit to an SVG is lost the next time the generator runs. For a lasting change, edit the Python and regenerate.
- **Details 3–8, 11 and 12** (CAD renders) ship as PNG only. To change a label, a callout or the view angle, edit `assembly_cad.py` and regenerate. To change geometry, edit `cad/pip_robot/` and follow [cad/README.md](../cad/README.md). The exploded views only move whole parts for display (the `offset` values). They do not alter the CAD and are not an assembly path. `servo_split()` separates the servo envelope's horn from its body for display only, so the horn can be shown off the spline.

## Limits

- The wiring diagrams show what connects to what. They do not show terminal order, connector orientation, bank port positions or cable routes. The drawn order of the bank's ports is arbitrary.
- The CAD renders use placeholder sizes for bought parts. Fastener markers sit on CAD hole positions and are approximate.
- The cable route in Detail 8 is drawn over the render and is proposed only. The camera in-line switch holder and the atmospheric sensor mount are not modelled.
- Details 10 and 2 contain blank record fields. Nothing in any image is a measured value or a test result.
- Status badges (HOLD, STOP, FUTURE, NOT SELECTED, UNVERIFIED) follow the docs at the time of generation. When a status changes in the docs, update the badge text here.
